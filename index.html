The through-line

Build it, scale it, re-architect it — 4 times, across 4 domains.

Most data leaders run one machine well. The scarce thing is the judgment for what to build next and how to organize humans and AI around it — and that judgment is only provable by repetition, not by one good run. Here it is, four times.

How I operate

Principles that outlast the tooling.

Build for the era after this one

Every system I ship assumes the next paradigm is already coming. The re-architecture is designed in, not bolted on later.

Contracts over heroics

Reliability, definitions, and data quality become guarantees the org can lean on — not tribal knowledge held by whoever is on call.

Own the outcome, not the dashboard

The point of a data function is decisions and P&L moved. I’ve run the charter, not just served it.

Talent is a design problem

Staffing should never be reduced to headcount planning. I build high-performing teams — deliberately, with vision and purpose.
